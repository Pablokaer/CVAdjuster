# CV Fit AI for Android

The Android app is a [Trusted Web Activity](https://developer.chrome.com/docs/android/trusted-web-activity) (TWA): a thin Android shell that opens https://cvfitai.com full screen in Chrome, without the browser bar. Updates to the site reach the app immediately; a new app build is only needed to change the icon, name, colors or version.

The Android project is generated by [Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap) from `twa-manifest.json`. Only that file is committed; the generated project, signing keys and build output stay out of git.

## What the site provides

| Path | Purpose |
|---|---|
| `/manifest.webmanifest` | Name, colors, icons and start URL |
| `/sw.js` | Service worker; only caches the offline page, never user pages |
| `/offline.html` | Shown when the app opens without a connection |
| `/icons/*` | Launcher icons (regular and maskable) |
| `/.well-known/assetlinks.json` | Proves the app and the site belong together; without it Android shows a browser bar |

## In-app purchases

Google Play only allows Play Billing for digital goods such as credits. Inside the app, everything that sells credits is hidden: the pricing section, the buy buttons, the "Add credits" links and the Stripe note. The app opens `/?source=twa`, which marks the browsing session as in-app (see `templates/fragments/app-shell.html`); elements with `purchase-only` are hidden there and `app-only` ones shown. The same account still has its credits, whichever way they were bought.

Do not add links or text inside the app that send users to buy on the website: Play treats that as steering to another payment method.

## Store listing

Texts, graphics and the Data safety answers for Play Console are in [`store/`](store/LISTING.md). The privacy policy is at `https://cvfitai.com/privacy` and the account deletion page at `https://cvfitai.com/delete-account`.

## First build

Requirements: Node.js 18+. Bubblewrap downloads its own JDK and Android SDK on the first run.

```bash
npm install -g @bubblewrap/cli
cd android

# Creates the upload key the first time (keep it and its passwords safe, outside git),
# then generates the Android project from twa-manifest.json.
bubblewrap update --manifest=./twa-manifest.json
bubblewrap build
```

`bubblewrap build` produces `app-release-bundle.aab` (upload this to Play) and `app-release-signed.apk` (for installing on a device with `adb install`).

If Bubblewrap asks to create the project instead, run `bubblewrap init --manifest=https://cvfitai.com/manifest.webmanifest` in this folder and answer with the values from `twa-manifest.json` (package `com.cvfitai.app`, start URL `/?source=twa`).

## Asset links (required for full screen)

1. In Play Console, create the app and enable Play App Signing.
2. Copy the **SHA-256 certificate fingerprint** of the *app signing key* from Test and release > App integrity > App signing. For local testing with the APK, also take the upload key's fingerprint: `keytool -list -v -keystore cvfitai-upload.keystore`.
3. On the server, add to the app's environment file (comma separated, both keys if you test locally signed APKs):

   ```
   APP_ANDROID_PACKAGE_NAME=com.cvfitai.app
   APP_ANDROID_SHA256_FINGERPRINTS=AA:BB:...,CC:DD:...
   ```

4. Restart the service and check `https://cvfitai.com/.well-known/assetlinks.json` returns the JSON. Google's [Statement List tester](https://developers.google.com/digital-asset-links/tools/generator) validates it.

If the browser bar shows at the top of the app, the asset links are missing or the fingerprint does not match the key that signed the installed build.

## Releasing an update

Site changes need no release: the app loads the live site. Release a new build only when the Android shell changes (name, icon, colors, start URL in `twa-manifest.json`, the Bubblewrap version, or Google's yearly target SDK requirement).

Releases are built and uploaded by [`.github/workflows/android-release.yml`](../.github/workflows/android-release.yml):

```bash
git tag android-v1.0.1
git push origin android-v1.0.1
```

or Actions > Android release > Run workflow, which also lets you pick the track (internal by default) and the version code. The workflow sets the version name from the tag, uses the run number + 1 as the version code (Play rejects a repeated one), builds and signs the bundle with the upload key, and uploads it to Play. The `.aab` and `.apk` are also kept as run artifacts for 30 days. Pull requests that touch `twa-manifest.json` or the workflow only build the app, with a throwaway key.

### One-time setup

The very first `.aab` must be uploaded by hand in Play Console; the API cannot create the app's first release.

1. In Google Cloud Console, enable the **Google Play Android Developer API** in a project and create a service account with a **JSON key**.
2. In Play Console > Users and permissions, invite the service account's email and give it permission to release to testing tracks (and production, if wanted) for CV Fit AI.
3. In GitHub > Settings > Secrets and variables > Actions, add:

   | Secret | Value |
   |---|---|
   | `ANDROID_KEYSTORE_BASE64` | The upload keystore in base64 (`base64 -w0 cvfitai-upload.keystore`, or `[Convert]::ToBase64String([IO.File]::ReadAllBytes("cvfitai-upload.keystore"))` in PowerShell) |
   | `ANDROID_KEYSTORE_PASSWORD` | The keystore password |
   | `ANDROID_KEY_PASSWORD` | The password of the `upload` key |
   | `PLAY_SERVICE_ACCOUNT_JSON` | The service account's JSON key |

With Play App Signing this is only the upload key: if it leaks, Google can replace it. Keep an offline backup anyway.

While the app has never been published, Play only accepts releases with status `draft`; run the workflow by hand with status `draft` and roll the release out in Play Console.

To build by hand instead, set `appVersion` and a new `appVersionCode` in `twa-manifest.json`, then run `bubblewrap update --skipVersionUpgrade` and `bubblewrap build`, and upload the `.aab`.
